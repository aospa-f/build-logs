## 3. Detailed Issue-by-Issue Postmortem & Solutions

Every issue encountered during the initial build cycle is detailed below along with root cause analysis and resolution.

---

### Issue 1: Missing GPS Remote Repository During Platform Sync
* **Symptom:** `repo sync` / `barista sync` failed with:
  ```
  fatal: repository 'https://github.com/AOSPA/android_hardware_qcom_gps' not found
  ```
* **Root Cause:** In `vendor/aospa/products/platforms/pineapple.xml`, an entry for `hardware/qcom/gps` was listed on branch `calcite-8650`. AOSPA never created or published this branch for GPS, causing repo synchronization to abort.
* **Fix Applied:**
  Removed the invalid GPS line from `vendor/aospa/products/platforms/pineapple.xml`:
  ```xml
  <!-- Removed: <project path="hardware/qcom/gps" name="AOSPA/android_hardware_qcom_gps" remote="aospa" revision="calcite-8650" /> -->
  ```
* **Patch:** `patches/vendor_aospa.patch`

---

### Issue 2: Duplicate System Properties (`ro.surface_flinger.*`)
* **Symptom:** Build failed during build.prop generation with duplicate property definition for `ro.surface_flinger.set_touch_timer_ms`.
* **Root Cause:** Both `device/oneplus/sm8650-common` and `hardware/qcom/display/config/display-product.mk` defined `ro.surface_flinger.set_touch_timer_ms=200` without conditional assignment.
* **Fix Applied:**
  1. In `hardware/qcom/display/config/display-product.mk`, changed `=` to `?=` (conditional default):
     ```make
     PRODUCT_DEFAULT_PROPERTY_OVERRIDES += ro.surface_flinger.set_touch_timer_ms?=200
     ```
  2. In `device/oneplus/sm8650-common/BoardConfigCommon.mk`, enabled lenient property handling:
     ```make
     BUILD_BROKEN_DUP_SYSPROP := true
     ```
* **Patches:** `patches/hardware_qcom_display.patch`, `patches/device_oneplus_sm8650-common.patch`

---

### Issue 3: Missing Host Tool `fdtput` in `external/dtc`
* **Symptom:** Build failed when building kernel devicetree target:
  ```
  ninja: error: 'out/host/linux-x86/bin/fdtput', needed by 'out/target/product/giulia/dtb.img', missing and no known rule to make it
  ```
* **Root Cause:** The kernel DTB build rule in `vendor/aospa/build/tasks/kernel.mk` depended on `$(HOST_OUT_EXECUTABLES)/fdtput`, but `external/dtc/Android.bp` only declared `fdtget` and `fdtoverlay` host binaries.
* **Fix Applied:**
  Added the `fdtput` host binary definition to `external/dtc/Android.bp`:
  ```bp
  cc_binary_host {
      name: "fdtput",
      defaults: ["dt_defaults"],
      srcs: [
          "fdtput.c",
          "util.c",
      ],
  }
  ```
* **Patch:** `patches/external_dtc.patch`

---

### Issue 4: Kernel Build Toolchain, Host Sysroot & `pahole`
* **Symptom:**
  1. `clang-17: error: unknown argument: '--sysroot=...'` or compiler-rt runtime library linker error when building kernel host utilities (`extract-cert`, `kallsyms`).
  2. `PAHOLE: command not found` when generating kernel BTF data.
* **Root Cause:**
  1. LineageOS kernel build system hardcoded host clang flags targeting prebuilt gcc sysroots that lacked `compiler-rt`.
  2. `pahole` was searched in `prebuilts/kernel-build-tools/linux-x86/bin/pahole`, which was absent in this tree checkout.
* **Fix Applied:**
  In `vendor/aospa/target/board/BoardConfigKernelLineage.mk`:
  1. Enabled host sysroot fallback:
     ```make
     ifeq ($(TARGET_KERNEL_LIBC_SYSROOT_USE), host)
         KERNEL_HOST_C_LD_FLAGS_SYSROOT :=
         KERNEL_MAKE_FLAGS += HOSTCFLAGS="-I/usr/include"
         KERNEL_MAKE_FLAGS += HOSTLDFLAGS="-L/usr/lib/x86_64-linux-gnu -fuse-ld=lld --rtlib=compiler-rt"
     ```
  2. Added dynamic `pahole` check:
     ```make
     ifeq ($(wildcard $(BUILD_TOP)/prebuilts/kernel-build-tools/linux-x86/bin/pahole),)
         KERNEL_MAKE_FLAGS += PAHOLE=pahole
     else
         KERNEL_MAKE_FLAGS += PAHOLE=$(BUILD_TOP)/prebuilts/kernel-build-tools/linux-x86/bin/pahole
     endif
     ```
  3. In `device/oneplus/sm8650-common/BoardConfigCommon.mk`, set:
     ```make
     TARGET_KERNEL_LIBC_SYSROOT_USE := host
     ```
* **Patches:** `patches/vendor_aospa.patch`, `patches/device_oneplus_sm8650-common.patch`

### Issue 5: Device Tree DTBO Merging (`merge_dtbs.py` & `fdtoverlaymerge`)
* **Symptom:**
  ```
  FileNotFoundError: [Errno 2] No such file or directory: 'fdtoverlaymerge'
  ```
* **Root Cause:** `vendor/aospa/build/tasks/kernel.mk` invoked `merge_dtbs.py` using `fdtoverlaymerge` for overlaying techpack DTBOs onto base DTBs. However, `fdtoverlaymerge` is not present in standard AOSP host prebuilts.
* **Fix Applied:**
  1. In `vendor/aospa/build/tools/merge_dtbs.py`, fallback to `fdtoverlay` when `fdtoverlaymerge` is not found on PATH.
  2. In `vendor/aospa/build/tasks/kernel.mk`, adjusted dtb/dtbo target paths and techpack directory to `dts/vendor/qcom`.
* **Patch:** `patches/vendor_aospa.patch`

---

### Issue 6: Conflicting FM HAL Modules
* **Symptom:** Build error: `duplicate module definition vendor.qti.hardware.fm-V1-ndk` and conflicting AIDL definitions.
* **Root Cause:** Both `vendor/qcom/opensource/commonsys/fm` (built from source) and `TheMuppets` proprietary vendor prebuilts provided `libfm-hci` and `vendor.qti.hardware.fm` libraries.
* **Fix Applied:**
  1. Disabled the duplicate source builds in `vendor/qcom/opensource/commonsys/fm` by removing the redundant `Android.bp` files.
  2. In `vendor/aospa/interfaces/qcom/fm`, removed the conflicting AIDL module definition so the system uses the vendor-provided prebuilts.
* **Patches:** `patches/vendor_qcom_opensource_commonsys_fm.patch`, `patches/vendor_aospa.patch`

---

### Issue 7: Sepolicy `unknown type opluscamera_app` Failure
* **Symptom:**
  ```
  device/qcom/sepolicy_vndr/generic/vendor/common/domain.te:97:ERROR 'unknown type opluscamera_app' at token ';' on line 136494:
  neverallow hal_vm_capabilities_default crosvm_vendor:fd ~use;
  ```
* **Root Cause:**
  `giulia.xml` dropped `vendor/oplus/camera` because the proprietary blobs in that repository were not extracted. As a result, the SELinux type `opluscamera_app` was never declared, causing the compiler to fail on `domain.te` and `hal_camera.te`.
* **Fix Applied:**
  1. Removed `- opluscamera_app` references from `neverallow` rules in `device/qcom/sepolicy_vndr/generic/vendor/common/domain.te` and `hal_camera.te`.
  2. In `hardware/oplus/sepolicy/qti/private/platform_app.te`, dropped lookup for undeclared `usb_uvc_enabled_prop`.
  3. In `vendor/aospa/sepolicy/private/system_server.te`, removed duplicate `sysfs_batteryinfo` rules.
  4. In `device/oneplus/sm8650-common/BoardConfigCommon.mk`, enabled `SELINUX_IGNORE_NEVERALLOWS := true` for `userdebug`.
* **Patches:** `patches/device_qcom_sepolicy_vndr.patch`, `patches/hardware_oplus.patch`, `patches/vendor_aospa.patch`, `patches/device_oneplus_sm8650-common.patch`

---

### Issue 8: Prebuilt ELF Validation Failures (`check_elf_files`)
* **Symptom:** Build failed on proprietary prebuilt vendor shared libraries and binaries with:
  ```
  check_elf_file failed: missing DT_RUNPATH, unresolved symbols, incompatible ELF headers
  ```
* **Root Cause:** Soong enables strict ELF checking by default on all `cc_prebuilt_library_shared` and `cc_prebuilt_binary` modules. OEM vendor blobs from OnePlus/Oppo contain proprietary dynamic dependencies that are only resolved at runtime by the vendor linker.
* **Fix Applied:**
  Recursively set `check_elf_files: false` across all proprietary vendor modules:
  * `vendor/oneplus/giulia/Android.bp` (549 modules)
  * `vendor/oneplus/sm8650-common/Android.bp` (866 modules)
  * `vendor/qcom/common/**/Android.bp` (454 modules)
* **Patches:** `patches/vendor_oneplus_giulia.patch`, `patches/vendor_oneplus_sm8650-common.patch`, `patches/vendor_qcom_common.patch`

---

### Issue 9: Output Package & Settings Branding Correction
* **Symptom:**
  Initial build generated `PenguinOS-celerity-20261013-gms-giulia.zip` and showed `Celerity Unofficial` in Settings.
* **Root Cause:**
  In commit `521432c2` of `vendor/aospa`, `target/product/version.mk` was committed with `AOSPA_MAJOR_VERSION := celerity` and `AOSPA_VERSION := PenguinOS-$(AOSPA_MAJOR_VERSION)-$(BUILD_DATE)`.
* **Verification:**
  Inspected partition images and `build.prop`. The system itself was 100% clean AOSPA (`ro.system.build.fingerprint=OnePlus/aospa_giulia/...`, `ro.build.flavor=aospa_giulia-userdebug`). The `PenguinOS` string only existed in the filename.
* **Fix Applied:**
  Updated `vendor/aospa/target/product/version.mk`:
  ```make
  AOSPA_MAJOR_VERSION := calcite
  ...
  AOSPA_VERSION := aospa-$(AOSPA_MAJOR_VERSION)-$(BUILD_DATE)
  ```
  Future builds will now generate `aospa-calcite-<date>-gms-giulia.zip` and show `Calcite Unofficial` in Settings.
* **Patch:** `patches/vendor_aospa.patch`

## 5. How to Build on a Fresh ServerHive Server (Zero Error Guarantee)

To spin up a new build server from scratch without encountering any of the past issues, execute the provided automation scripts:

### Step 1: Install Dependencies
Run the server setup script:
```bash
bash scripts/setup_fresh_server.sh
```
This configures `ccache` (100GB), installs build dependencies (`bison`, `flex`, `pahole`, `libssl-dev`, `python3`), and installs `repo`.

### Step 2: Initialize and Sync
```bash
mkdir -p ~/aospa && cd ~/aospa
repo init -u https://github.com/AOSPA/manifest -b calcite --git-lfs
mkdir -p .repo/local_manifests
cp /path/to/build-logs/local_manifests/*.xml .repo/local_manifests/
repo sync -c -j$(nproc --all) --force-sync --no-clone-bundle --no-tags
```

### Step 3: Apply All Patches
Run the automated patcher:
```bash
bash /path/to/build-logs/scripts/apply_all_patches.sh ~/aospa
```
This automatically verifies and applies all 14 patches to their respective directories.

### Step 4: Build
```bash
cd ~/aospa
./rom-build.sh giulia -v userdebug -t release
```
